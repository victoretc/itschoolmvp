### 2.3. Подводные камни Hugo, которые уже наступили

Эти грабли проверялись экспериментально — учтём их во всех остальных фазах (особенно в OG-описаниях и schema, где текста больше).

| Грабля | Поведение | Как обходить |
|---|---|---|
| **Кавычки в атрибуте + `--minify`** | Hugo пересериализует атрибут в двойные кавычки и двойно экранирует внутренние `'` и `"` → `&amp;#39;` / `&amp;#34;` | Убирать оба вида кавычек из значений атрибутов **до** вывода |
| **Переносы строк в атрибуте** | `plainify` сохраняет `\n` из HTML → атрибут разрывается, часть парсеров и сниппетов ломается | `replaceRE "\\s+" " "` |
| **`&` в атрибуте** | Одиночный `&` — невалидный HTML | Сначала `replaceRE "&[#0-9a-zA-Z]+;" ""`, потом `replaceRE "&" ""` |
| **NBSP (`\xa0`)** | `\s` в RE2 не матчит NBSP — пробелы-неразрывки остаются | `replaceRE "\xc2\xa0" " "` |
| **`trim` с пайпом** | `trim INPUT CUTSET`, а пайп всегда идёт **последним** аргументом → `trim " "` схлопывает литерал, а не значение | Не использовать `trim` в пайпе. Вместо него `replaceRE "^ +\| +$" ""` |
| **`htmlUnescape` меняет тип на `template.HTML`** | После него `plainify` ведёт себя иначе и даёт `&#34;` вместо `"` | Не ставить `htmlUnescape` **перед** `plainify` |
| **Переменная-пайп** | `$x := "a \| b"` → `can't give argument to non-function $x` | Функцию нельзя вынести в переменную — только инлайн или `if/else` |
| **Переменная в `if`-блоке** | `{{ $x := ... }}` внутри `if` не видна снаружи блока | Объявлять `{{ $x := "" }}` до `if` и присваивать через `=` |

**Проверенный рабочий пайп для текста в атрибутах:**
```
plainify | replaceRE "&[#0-9a-zA-Z]+;" "" | replaceRE "&" "" | replaceRE "[\"']" "" | replaceRE "\xc2\xa0" " " | replaceRE "\\s+" " " | truncate 160
```

### 3.2. Старые изображения (`/wp-content/uploads/*`)

Старый WP отдаёт ~150+ файлов в `/wp-content/uploads/`. Они используются:
- в `og:image` старых страниц,
- в `Яндекс.Картах` и `Instagram`,
- в поиске Google Images по старым URL.

**Решение:** перенести нужные файлы в `static/uploads/` нового сайта и настроить на старом сервере:
```
location ^~ /wp-content/uploads/ {
    return 301 /uploads/$1;   # или на новый хост
}
```
Альтернатива — отдать старые файлы как есть ещё 12 месяцев (без 301), чтобы не сломать внешние ссылки и Google Images.

### 3.3. Где живут редиректы

**Рекомендуемый вариант — тот же nginx (IP не меняется, DNS не трогаем):**

```nginx
# /etc/nginx/conf.d/it-school-redirects.conf
server {
    listen 80;
    server_name it-school.by www.it-school.by;
    return 301 https://it-school.by$request_uri;
}

server {
    listen 443 ssl http2;
    server_name it-school.by www.it-school.by;

    # --- редиректы со старых URL WordPress ---
    location = /blog/                { return 301 https://it-school.by/about/; }
    location = /it-caniculy/         { return 301 https://it-school.by/it-vacations/; }
    location = /ura-nashi-deti-molodczy/ { return 301 https://it-school.by/about/#results; }
    location = /vesennie-it-kanikuly/     { return 301 https://it-school.by/about/#results; }
    location = /category/articles/   { return 301 https://it-school.by/about/; }
    location = /tag/articles/        { return 301 https://it-school.by/about/; }
    location = /author/admin/        { return 301 https://it-school.by/about/; }
    location = /feed/                { return 301 https://it-school.by/index.xml; }
    location = /comments/feed/       { return 301 https://it-school.by/index.xml; }
    location ^~ /wp-json/            { return 301 https://it-school.by/; }
    location = /xmlrpc.php           { return 301 https://it-school.by/; }
    location = /wp-login.php         { return 301 https://it-school.by/; }
    location = /wp-admin/            { return 301 https://it-school.by/; }

    # --- отдача нового статического сайта ---
    root /var/www/it-school;
    index index.html;

    location / {
        try_files $uri $uri/ =404;
    }
    error_page 404 /404.html;
}
```

> **Важно:** редиректы должны отдавать **одним хопом** 301 на абсолютный `https://it-school.by/...`. Не делать цепочек (`/blog/ → /about/ → /`).

2. **Где хостим?** Рекомендую тот же nginx. Подтвердить, или выбираем GitHub Pages / Cloudflare.
3. **Правильный юридический адрес?** В `data/site.yaml` — `ул. Пионерская, 52, к. 503`, на сайте и в картах — `просп. Машерова, 23А, 4 этаж`. Для локального SEO адрес должен совпадать в Schema, на сайте и в Яндекс.Картах.
4. **Есть ли доступ к Яндекс.Вебмастеру и GSC?** Нужны для baseline, мониторинга и подтверждения доменов.
5. **Филиалы Жабинка / Пинск / Кобрин — это отдельные классы с отдельными адресами?** От этого зависит, делать ли landing-страницы (задача 6.5).
6. **Какие реальные поисковые запросы дают трафик сейчас?** Без Search Console тайтлы из §2.1 — гипотезы. Нужен экспорт из Яндекс.Вебмастера (поисковые запросы) и GSC.
7. **Телефоны:** на старом сайте `+375 (29) 871-76-12` и `+375 (29) 228-49-71`. Какой основной, а какой в филиалы?
8. **Рейтинг 4.5 / 17 отзывов** — это Яндекс.Карты. Использовать в `AggregateRating`? Google может счесть это недостоверным, если отзывы не на странице. Нужен текстовый блок с отзывами на `/about/`.
